In C++, std::vector provides the erase() method to remove elements. However, erasing multiple elements in a loop requires careful handling to avoid iterator invalidation and skipped elements.

🧠 What Happens Under the Hood During a Vector Erase?

To understand why iterator invalidation happens, you have to look at how a std::vector manages memory. A vector stores its elements in a contiguous block of memory (right next to each other, like a raw array).

The Shuffle Effect

When you call nums.erase(it), the vector doesn't leave a hole or shrink the memory block. Instead, it performs a destructive shift operation:

  1. The element at the current iterator position is destroyed.
  2. Every single element after that position must be shifted left by one slot to close the gap and maintain contiguous memory.
CRITICAL CONCEPT: Because elements are physically copied or moved to a new memory slot during the shift, any existing iterator pointing to those shifted slots is now pointing to modified data or out-of-bounds memory. This is Iterator Invalidation.

Visualizing the Bug vs. The Fix

Imagine iterating through a vector of nums = {1, 2, 3, 4} and trying to remove the even numbers using a naive loop:

1. The Erase Step

The iterator finds 2 at index 1 and erases it.

{ 1, [2], 3, 4 }

2. The Under-the-Hood Shift

C++ immediately shifts 3 and 4 to the left to close the gap. The vector is now { 1, 3, 4 }.

Notice that 3 is now sitting at index 1 (where 2 used to be)!

3. The Naive Bug (Why elements get skipped)

If your loop blindly runs a standard ++it or i++ right after erasing, your iterator moves to index 2.

Index 2 now holds 4. The number 3 was completely skipped without ever being checked by your if condition!

💡The Fix: By assigning it = nums.erase(it);, C++ hands you a fresh, valid iterator pointing exactly to the element that just slid into that slot (the 3). By skipping the ++it on an erase step, your loop safely checks that new element on the next iteration.

🔹 The Problem: Iterator Invalidation

When you erase an element from a vector using erase(), all iterators after the erased element become invalid. If you're iterating through the vector and erasing elements, this can lead to:

  • Accessing invalid memory
  • Skipping elements unintentionally
  • Undefined behavior

🔸 Safe Pattern for Erasing in a Loop

To safely erase multiple elements, use a for loop with an iterator, only increment the iterator if no erasure occurs.

✅ Example: Remove All Even Numbers

#include <iostream>
#include <vector>

int main() {
    std::vector<int> nums = {1, 2, 3, 4, 5, 6, 7, 8};

    for (auto it = nums.begin(); it != nums.end(); ) {
        if (*it % 2 == 0) {
            it = nums.erase(it);  // erase returns the next valid iterator
        } else {
            ++it;  // only increment if no erase
        }
    }

    // Output the result
    for (int n : nums) {
        std::cout << n << " ";
    }
    return 0;
}

🧠 Key Insight:

  • erase(it) removes the element and returns a valid iterator pointing to the next element.
  • If you increment the iterator after erase(), you skip the next element.

🔹 Alternative: Reverse Iteration

If you're removing elements based on index or position, iterating backward can be safer:

for (int i = nums.size() - 1; i >= 0; --i) {
    if (nums[i] % 2 == 0) {
        nums.erase(nums.begin() + i);
    }
}

✅ Why This Works:

  • Erasing from the end avoids invalidating earlier indices.
  • No iterator invalidation occurs for elements before the erased one.

🔹 Alternative: for loop Iteration

If you're removing elements based on index, make sure to only increment the for loop variable when NOT erasing.

for (int i = 0; i < nums.size(); ) //NOTE: no i++ here
{
    if (nums[i] % 2 == 0) {
        nums.erase(nums.begin() + i);
    }
    else {
        i++; //only increment i when NOT erasing
    }
}

🧠 Best Practices

  • Prefer iterator-based loops when working with erase().
  • Avoid range-based for loops when modifying the container.
